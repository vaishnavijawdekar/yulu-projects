# Contributing to yulu-projects

Thanks for adding your project to the Yulu hub! This is meant to be lightweight — no formal process, just clear info so others can discover and use what you've built.

## What belongs here?

Anything Yulu-related built by Yulu PMs, designers, engineers, or workshop attendees:
- Production tools and dashboards
- Internal experiments and prototypes
- Workshop exercises and demos
- AI agents, automations, scripts
- Research projects and analyses

## How to add your project

You have two paths. Pick the one that feels easiest.

### Path 1 — Issue form (no git needed)

1. Click here to [open a new "Add a project" issue](../../issues/new?template=add-project.yml).
2. Fill in the form fields (project name, repo URL, what it does, owner, etc.).
3. Submit. A maintainer will convert your issue into a README entry within a few days.

This is the easiest path if you're not comfortable editing markdown or opening a PR.

### Path 2 — Direct PR

1. Fork this repo.
2. Edit `README.md` — add your project as a new entry under **Production / Live Tools**.
3. Use the same card format as existing entries (see below).
4. Open a PR. Fill in the PR template checklist.

### Entry format

Copy and adapt this template:

```markdown
### project-name
One-line description of what the project does and why it exists.

- **Repo:** https://github.com/owner/project-name
- **Live:** https://your-deploy-url.com  (omit if not deployed)
- **Owner:** @your-github-username
- **Tech:** comma, separated, list, of, main, tools
- **Status:** Live | WIP | Archived
- **Ownership:** Official Yulu | Personal experiment (Yulu-themed)
```

## Quality bar

We'll merge your entry as long as:
- The project is genuinely Yulu-related (Yulu workflows, brand, data, team, or training).
- The linked repo (or folder) has at least a README explaining what it is.
- The "Ownership" tag is honest — be clear whether this is official company work or a personal experiment that happens to be Yulu-themed.

## Updating an existing entry

If a project you own has changed (new URL, archived, new owner, etc.) — open a PR or issue to update it. Don't wait for the original author.
